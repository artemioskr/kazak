# План проекта: прогноз активности рыбы («ФишКаст»)

## 1. Концепция

Веб-приложение (позже — PWA на телефон): пользователь ставит точку на карте, выбирает целевой вид и тип водоёма, получает почасовой прогноз активности рыбы на 3–7 дней вперёд с объяснением, *почему* оценка такая. Ключевое отличие от готовых «клёвометров» — прозрачность факторов и калибровка по собственному журналу рыбалок.

**Главный сценарий (под себя):** джиг на судака/берша/щуку, Нижнекамское водохранилище, выезд планируется за 1–3 дня.

---

## 2. MVP (этап 1, ~2–4 недели вечерами)

Минимум, который уже полезен:

- Точка на карте (Leaflet + OSM), сохранённые точки.
- Open-Meteo: почасовое давление, ветер, облачность, температура, осадки — прогноз 7 дней + архив 2 суток назад (для тренда давления).
- Солунарный расчёт локально (major/minor периоды, фаза Луны).
- Восход/заход солнца и луны.
- Скоринг 0–100 по часам, график на сутки, сводка по дням.
- Расшифровка: «−15: резкий рост давления за 6 ч», «+20: major-период + сумерки».

Без регистрации, без БД пользователей — одна страница, конфиг в localStorage.

## 3. Этап 2 — данные и точность

- **Тренд давления** по архиву: дельты за 3/6/12/24/48 ч, детект фронта (давление + разворот ветра + скачок T).
- **Модель температуры воды**: сглаженная температура воздуха с инерцией по типу водоёма (пруд ~1–2 дня, водохранилище ~5–7 дней). Позже — ручная корректировка «померил на рыбалке».
- **Уровень/сброс воды**: для Нижнекамского — данные РусГидро/АИС ГМВО по гидропостам. Сброс с ГЭС = течение = активность судака на бровках. Это фактор, которого нет ни в одном готовом клёвометре — потенциально главная фишка.
- **Сезонный профиль по видам**: преднерестовый ход, нерестовый запрет (по Удмуртии/Татарстану — вывести предупреждением!), посленерестовое, летний термоклин, осенний жор, перволёдье, глухозимье.
- **Kp-индекс** (NOAA SWPC) — слабый вес, но дёшево.
- Второй источник погоды (Яндекс/OpenWeatherMap) — сравнение прогнозов; расхождение источников само по себе сигнал неопределённости.

## 4. Этап 3 — журнал и калибровка

- Журнал рыбалок: дата/время, точка, вид, снасть, улов, субъективная оценка клёва 1–5, температура воды факт.
- Автопривязка: при записи сохранять снапшот всех факторов на тот час.
- Раз в сезон — пересчёт весов: хотя бы линейная регрессия / логистика по своим записям. Данных мало — не лезть в нейросети, максимум градиентный бустинг когда записей >100.
- Импорт треков/точек с Lowrance (GPX/USR) — привязка уловов к структурам.

## 5. Скоринговая модель (черновик)

```
score = base_season(вид, дата, T_воды)
      + w1 * f_давление(тренд 6/24ч)
      + w2 * f_фронт(до/во время/после)
      + w3 * f_ветер(скорость, направление к точке)
      + w4 * f_облачность(вид: хищник любит пасмурно)
      + w5 * f_время_суток(сумерки, день, ночь)
      + w6 * f_солунар(major/minor, фаза)
      + w7 * f_течение(сброс ГЭС)   // для водохранилища
      + w8 * f_kp
```

- Веса и формулы — в конфиге (JSON/таблица в БД) с версионированием, не в коде.
- Отдельные профили весов на вид: судак ≠ щука ≠ лещ.
- Нормировка в 0–100 + категория (плохо/средне/хорошо/отлично).
- Каждый фактор возвращает и вклад, и текст-объяснение — для расшифровки в UI.

## 6. Стек (предложение)

- **Бэкенд:** PHP 8 + Slim/Laravel или Python + FastAPI — что ближе. PostgreSQL (уже родной). Кэш ответов погодных API (они лимитированы) — таблица или Redis.
- **Расчёты луны/солнца:** PHP — `solarium/astronomy-bundle` или порт suncalc; Python — `astral`/`skyfield`.
- **Фронт:** одна SPA-страница, Leaflet, график — Chart.js/ECharts.
- **Крон:** раз в час тянуть прогнозы по сохранённым точкам, чтобы UI открывался мгновенно.
- PWA-манифест — иконка на телефон, офлайн-кэш последнего прогноза.

## 7. Идеи на потом

- Пуш «завтра окно: падающее давление + major на рассвете + сброс 1200 м³/с».
- Сравнение «прогнозировали / что было по журналу» — честная статистика точности.
- Ледовая модель зимой: сумма градусо-дней мороза → оценка толщины льда (с большим дисклеймером).
- Карта ветра на водоёме: с какого берега прижим, где волна — для лодки актуально.
- Телеграм-бот как альтернативный интерфейс (дешевле, чем мобильное приложение).
- Мультипользовательский режим и общие точки — только если самому зайдёт.

## 8. Риски и грабли

- **Лимиты API**: кэшировать всё, архив копить у себя — потом пригодится для калибровки.
- **Гидропосты**: данные АИС ГМВО бывают с задержкой и дырами; парсинг может ломаться — закладывать graceful degradation (нет данных → фактор выключен, а не ноль).
- **Переобучение на малых данных**: 20 рыбалок за сезон — это не датасет. Веса калибровать осторожно, вручную проверять.
- **Ложная точность**: показывать не только цифру, но и разброс/уверенность, иначе сам себе начнёшь верить больше, чем стоит.
- Нерестовый запрет — обязательно показывать даты по региону, чтобы приложение не «рекомендовало» ловлю в запрет.

## 10. Монетизация

### Модель: freemium-подписка

- **Бесплатно:** 1 сохранённая точка, прогноз на 3 дня, базовый скоринг без расшифровки по факторам. Бесплатная версия = воронка, она должна быть реально полезной.
- **Pro, 149–199 ₽/мес или 990–1290 ₽/год:** до 10 точек, прогноз 7 дней, пуши «окно клёва», данные ГЭС/уровней, журнал с аналитикой и калибровкой, карта ветра, профили по видам.
- Продавать выгоду, а не функции: «узнай окна клёва на неделю вперёд и не жги бензин зря» (выезд на лодке — 1–3 тыс ₽ топлива, подписка окупается одной отменённой пустой поездкой).
- Триал 14 дней без карты.

### Платежи и дистрибуция (реалии РФ)

- **PWA + сайт** — основной канал: ЮKassa или CloudPayments, СБП. Без комиссии сторов (30%) и проблем с оплатой в Google Play/App Store.
- **Телеграм-бот** — второй канал: оплата через Telegram Stars или встроенных провайдеров, аудитория уже там.
- **RuStore** — Android-обёртка PWA + RuStore Pay, когда появится трафик.
- App Store/Google Play — только если проект взлетит; сейчас это боль с оплатой из РФ.

### Легализация

- **Самозанятость (НПД):** 4–6% налога, лимит 2,4 млн ₽/год, совместима с основной работой по найму. Для старта достаточно, чеки формирует «Мой налог».
- Публичная оферта + политика обработки ПДн (152-ФЗ), как только появляются аккаунты и платежи.
- Переход на ИП (УСН 6%) — при выходе за лимит или для B2B-договоров.

### Расходы — критичный пункт

- ⚠️ **Open-Meteo бесплатен только для некоммерческого использования.** Платный продукт = коммерческий план от ~29 €/мес, либо смена источника. Проверить лицензии ВСЕХ источников до запуска платежей — это главная скрытая статья расходов.
- VPS 500–1500 ₽/мес, домен ~1000 ₽/год, эквайринг ~3,5% с платежа.
- Итого порог безубыточности — примерно 25–40 платящих подписчиков.

### Юнит-экономика, честно

- Рынок узкий и сезонный: пики — весна, осенний жор, перволёдье; провалы — глухозимье, нерестовый запрет.
- Типичная конверсия установок в платящих 2–5%. Чтобы получить 50 подписчиков (≈8–10 тыс ₽/мес), нужно ~1500–2500 активных бесплатных пользователей.
- Реалистичный потолок соло-проекта без бюджета на рекламу — 30–100 тыс ₽/мес через 1–2 сезона. Это «свечной заводик», не стартап — и это нормально.

### Каналы привлечения (бюджет ≈ 0)

- Бесплатный контент как воронка: еженедельный пост «прогноз клёва на выходные: Нижнекамское, Воткинское» в VK-сообществах и телеграм-каналах — сам прогноз и есть реклама.
- Рыболовные форумы (Русфишинг, местные), обзоры у рыболовных блогеров YouTube/Дзен (микроблогеры часто пишут обзор за Pro-доступ).
- Сарафан: реферальная ссылка «+1 месяц Pro за друга».

### B2B-ветка (после обкатки B2C)

- Виджет прогноза для сайтов рыболовных баз и гидов (фикс 1–3 тыс ₽/мес с базы).
- Партнёрки с магазинами снастей: промокоды, витрина «под условия» («ветер 8 м/с — джиг от 20 г»).

### Чего не делать

- Не включать платёжку, пока нет ~100+ регулярных бесплатных пользователей и работающего прогноза.
- Не обещать точность в оферте и маркетинге («вероятность активности», не «гарантия клёва») — и репутация, и юридическая безопасность.
- Не демпинговать навсегда: скидка раннему пользователю — да, «пожизненно за 99 ₽» — нет, это убивает подписочную модель.
